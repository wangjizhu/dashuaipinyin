# Windows 11 绿色纯净拼音输入法技术选型报告

（综合 6 份调研简报：TSF 前端、Google 拼音遗产、Rime 生态、引擎横评、竞品、词库/语言模型；调研时点 2026-07）

## 0. 需求与评估标准

目标：对标早年 Google 拼音（2.7.23，2013 年停更、2019 弃维护）的体验——整句转换好用、无广告、无隐私上传、轻量。评估优先级：**好用高效（整句准确率、响应速度）＞ 绿色纯净（无广告、零上传、可便携）＞ 开发可行性**。

两个先决事实：

1. **Windows 11 只能走 TSF**（IMM32 已被封杀）。TSF 输入法 = COM in-proc DLL 注入所有进程，注册需管理员权限，**完全免安装的"绿色"不可能**；"绿色"只能定义为：无广告、零联网零遥测、数据本地、单一安装包、卸载干净。竞品简报的反面清单（搜狗改主页/探测杀软、百度候选词广告、2021 年 15 款输入法被网信办通报）表明这个定位有真实市场空缺，且监管已认定"输入法基本功能无须收集任何个人信息"（https://www.cac.gov.cn/2021-04/30/c_1621370239178608.htm ）。
2. **"重制 Google 拼音"的生态位是空的，但其开源遗产撑不起体验**。PC 版组句引擎与大词库从未开源；开源的 AOSP 引擎（libgooglepinyin）只有 unigram + 6.5 万条 2009 年词库，上游全线死亡。见第 2 节。

## 1. 引擎选择对比

| 引擎 | 协议 | 整句能力 | 活跃度 | Windows 可用性 | 结论 |
|---|---|---|---|---|---|
| **librime** https://github.com/rime/librime | **BSD-3-Clause** | 好；配 octagram 插件 + 万象 gram 模型达开源最高：**句准 76.86%/字准 96.32%**（22.4 万句测试集，https://amzxyz.github.io/rime-wanxiang/doc/intro/ ） | 1.17.0（2026-06-06），nightly 滚动 | **官方 MSVC x64/x86 预编译直接可用**；C API 单头文件约 40 函数，一天跑通主循环 | **首选** |
| **libIME** https://github.com/fcitx/libime | LGPL-2.1+ | 好（kenlm n-gram，fcitx5 官方拼音引擎） | 最活跃（2026-07-14 当天 push），官方词典/LM 按月更新 | 无官方 Windows CI，需自建 Fcitx5Utils+Boost+zstd 构建链 | 备选；协议友好但移植成本高、无质量增量 |
| **libpinyin** https://github.com/libpinyin/libpinyin | GPL-3.0 | 好（bigram，ibus/fcitx 长期打磨） | 活跃（2.10.3，2025-09） | 依赖 GLib2，无 Windows CI | 仅纯 GPL 路线的备选 |
| **sunpinyin** https://github.com/sunpinyin/sunpinyin | CDDL/LGPL-2.1 | trigram，历史口碑好 | 濒死（2025-03 最后修补） | 无 Windows 端口，SCons+POSIX 需自行改造 | 不推荐（需接盘维护，open-gram 语料过时） |
| **libgooglepinyin**（AOSP PinyinIME）https://android.googlesource.com/platform/packages/inputmethods/PinyinIME/ | **Apache-2.0** | **弱：仅 unigram + 词格 DP，无上下文模型**（读 ngram.h 核实） | 死亡（2013/2015 停更，fcitx wrapper 2024 归档） | 1.25 万行无依赖 C++，随处可编译 | 不作引擎；作教材与保底词库 |
| LLM 引擎（lime 等）https://github.com/xushengfeng/lime | GPL-3.0 | 潜力大但早期（丢字、无记忆） | 新兴 | llama.cpp + Qwen3-0.6B | 中期预研"n-gram 打底 + 本地小模型重排"，不作主线 |
| **mozc** https://github.com/google/mozc | BSD-3 | （日文） | 非常活跃 | 官方 Windows TSF | 不是拼音引擎，但**进程分离架构（薄 TSF DLL ↔ 引擎进程 ↔ 渲染进程）是最佳蓝本** |

**引擎结论**：librime 在"质量（配万象模型）、Windows 落地成本（官方预编译）、协议（BSD）"三项同时占优。唯一雷区：加载 .gram 语言模型必须经 **librime-octagram 插件（GPL-3.0）**——解法是把引擎放独立服务进程经 IPC 与 TSF DLL 隔离（即 weasel/mozc 架构），或整体接受 GPL。

## 2. 前端选择对比

| 方案 | 协议 | 工作量 | 说明 |
|---|---|---|---|
| **复用 weasel 前端**（定制发行版）https://github.com/rime/weasel | GPL-3.0 | 0.5–2 人月 | WeaselTSF/WeaselServer/WeaselIPC/WeaselUI 架构完整，x86/x64/ARM64X，Windows 8.1–11；最经打磨的中文 TSF 实现；0.17.4（2025-06）+ nightly（2026-07-03），fxliang 事实主维护 |
| **自研 TSF 前端** | 自定 | **2–4 人月到可日用**（M1 骨架上屏 1–2 周；M2 组合+候选窗 3–6 周；M3 兼容性打磨 4–8 周且最耗人） | 骨架取 **MIT 的微软 SampleIME**（https://github.com/microsoft/Windows-classic-samples/tree/main/Samples/IME ，能跑但需修 DPI/触摸键盘）；兼容性处理参考 **BSD-3 的 DIME**（https://github.com/jrywu/DIME ，v1.3.644 2026-05，同为"零网络零收集"定位）；排坑参考 saschanaz/ime-rs、水杉输入法（单人一年半业余 → 校准工作量）、https://z-rui.github.io/post/2025/09/tsf-ime/ |
| PIME 框架 https://github.com/EasyIME/PIME | LGPL-2.1 | 低（原型） | C++ 薄 TSF + Python/Node 后端；适合快速验证，release 停滞（2023-01），不宜作产品底座 |
| google-input-tools client/ https://github.com/google/google-input-tools | Apache-2.0 | 参考 | 谷歌拼音 Windows 客户端同源壳层，2022 归档；Apache 协议的 IME 壳层参考件 |

**自研 TSF 必踩的硬坑**（已核实）：x86+x64 双 DLL 分别注册（https://learn.microsoft.com/zh-cn/windows/win32/tsf/64-bit-platform-considerations ）+ ARM64X；UWP/AppContainer（IMMERSIVESUPPORT category、DLL 须放 Program Files、数据文件 ACL）；per-monitor DPI（跟随宿主）；触摸键盘 PUA 键 0xF003/0xF004；light-dismiss 三事件 + UIA 属性（https://learn.microsoft.com/en-us/windows/apps/develop/input/input-method-editor-requirements ）；提权宿主与低完整性引擎进程间管道需放宽安全描述符；**发布必须买 Authenticode 代码签名证书**（IME DLL 注入所有进程，无签名必遭 SmartScreen/杀软围剿）。

## 3. 词库与语言模型方案

**按协议分两轨：**

- **宽松/闭源可用轨（推荐）**：主词库 + 语言模型用 **万象 rime-wanxiang（CC-BY-4.0，署名即可，2026-07-14 仍在 push）** https://github.com/amzxyz/rime-wanxiang + **RIME-LMDG gram 模型（CC-BY-4.0，LTS 版 400MB）** https://github.com/amzxyz/RIME-LMDG ；保底词库 AOSP rawdict（Apache-2.0，6.5 万条）；领域补充 THUOCL（MIT，2016 年数据偏旧）；新词/专名 fcitx5-pinyin-zhwiki（CC BY-SA，独立数据包分发）。
- **GPL 轨**：直接用**雾凇 rime-ice**（GPL-3.0，18.3k star，质量标杆，https://github.com/iDvel/rime-ice ）或**白霜 rime-frost**（GPL-3.0，7.45 亿字语料重刷词频，V2EX 横评称 Rime 系整句最佳，https://github.com/gaboolic/rime-frost ），叠加万象 gram 模型（CC-BY-4.0 与 GPL 兼容）。
- **红线**：**搜狗细胞词库任何路线都不得随包分发**（汇编作品 + 反不正当竞争风险）；只做"用户本地自行导入"，指引用户使用深蓝词库转换（GPL-3.0，只能外部工具调用，https://github.com/studyzy/imewlconverter ）。雾凇/白霜词库转成自有二进制即衍生作品，宽松协议产品不能内嵌。
- **用户词典**：本地 LevelDB/SQLite 自学习 + 明文 TXT/CSV 导入导出 + Rime 式 `sync_dir` 文件夹同步（用户自备 Syncthing/OneDrive）——零云端即卖点。
- **工程细节**：用 librime 的 `prebuilt_data_dir` 分发预编译 build 产物，跳过首启数十秒部署；400MB gram 模型做成安装时可选下载。

## 4. 可行路线对比

| | 路线一：定制 Weasel 发行版 | 路线二：自研 TSF + librime + 万象 | 路线三：自研 TSF + libIME | 路线四：libgooglepinyin 复刻 / 从零自研 |
|---|---|---|---|---|
| 整句质量 | **开源最高**（句准 76.86%/字准 96.32%） | 同左（同引擎同数据） | 好但无基准数据，缺专训 gram 模型 | 差（unigram，＜62% 句准水平；从零自研成本巨大） |
| 绿色纯净 | 满足（100% 本地） | 满足，且前端自控可做得更彻底 | 满足 | 满足 |
| 工作量 | **0.5–2 人月** | 4–6 人月 | 5–8 人月（含 Windows 移植踩坑） | 2–3 人月原型 / +6–12 人月自研引擎 |
| 协议 | **整体必须 GPL-3.0** | BSD+MIT+CC-BY-4.0，闭源可选（octagram 进程隔离） | LGPL 动态链接，闭源可行 | Apache-2.0 最干净 |
| 主要风险 | 差异化有限、上游不可控 | TSF 兼容性长尾、签名成本 | 自扛移植链维护、社区经验少 | 质量天花板违背第一诉求 |

## 5. 关键风险清单

1. **GPL 传染**：weasel 前端、octagram 插件、雾凇/白霜词库均 GPL-3.0——选型时必须先定"是否永久开源"，这是所有路线的分岔点。
2. **TSF 兼容性长尾**：自研前端 60–70% 工时耗在"每个宿主行为不一样"（Chrome/Word/终端/游戏/UWP/远程桌面），这是 2–4 人月估计的最大方差来源。
3. **签名与杀软**：无 Authenticode 证书的 IME 实际不可发布。
4. **体积与首启**：400MB gram 模型、首次部署数十秒——用可选下载 + prebuilt_data_dir 化解。
5. **词库残余风险**：社区词库声明协议 ≠ 上游语料完全无瑕疵（行业共同风险）；NOTICE 文件做全署名。
6. **变现**：V2EX 共识是个人输入法难收费，开源免费聚口碑 + 捐赠/企业定制更现实；一旦加广告即摧毁唯一差异化定位。

## 6. 推荐

**两阶段走**：

- **阶段一（首发，0.5–2 人月）：定制 Weasel 发行版**——fork weasel，预置万象（或雾凇）+ gram 模型 + 预编译词库，改默认值为"装完即好用"（简体、emoji、中英混输、GUI 设置），品牌化安装包，接受 GPL-3.0 整体开源。理由：按"好用高效＞绿色纯净＞可行性"的排序，它以最小成本直达最高可得质量，且开源正是纯净定位的最强信任背书（雾凇 18.3k star 已验证）。
- **阶段二（4–6 人月）：自研 TSF 前端 + librime 服务进程 + 万象数据**——SampleIME（MIT）做骨架、DIME（BSD）抄兼容性、mozc 架构做进程分离，把 GPL 的 octagram 隔离在引擎进程内，拿回前端自控权与协议自由度，重点补 Rime 生态的短板：零配置开箱即用、GUI 设置、明文词库导入导出、干净卸载。

不推荐 libgooglepinyin 作引擎（unigram 天花板 + 上游死亡）与完全从零自研引擎（无性价比）；libIME 仅当"必须闭源且不愿做进程隔离"时再评估。
