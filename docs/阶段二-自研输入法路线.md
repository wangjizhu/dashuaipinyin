# 阶段二：自研 TSF 前端 + librime 引擎（规划）

阶段一（当前发行版）验证产品定位后，阶段二的目标是**拿回前端完全自控权**，
补齐 Rime 生态公认短板：零配置开箱即用、GUI 设置面板、明文词库导入导出、干净卸载。

## 架构（照抄 mozc / weasel 的成熟模式）

```
┌─────────────宿主应用进程──────────────┐
│  薄 TSF DLL（x86 / x64 / ARM64X）      │  ← 只做按键转发与上屏，无业务逻辑
│  MIT 骨架：微软 SampleIME              │
└──────────────┬───────────────────────┘
               │ 命名管道 IPC（低完整性可访问的安全描述符）
┌──────────────▼───────────────────────┐
│  引擎服务进程（用户态单例）             │
│  librime C API（BSD-3）               │
│  + octagram 插件（GPL，隔离在本进程）   │  ← GPL 经进程边界隔离，前端可闭源/宽松协议
│  + 万象词库 + gram 模型（CC-BY-4.0）    │
└──────────────┬───────────────────────┘
               │
┌──────────────▼───────────────────────┐
│  候选窗渲染进程 / GUI 设置程序          │  ← Direct2D/DirectWrite，per-monitor DPI
└──────────────────────────────────────┘
```

## 必踩的硬坑清单（来自调研，动手前先读）

1. **多架构**：x86 + x64 双 DLL 分别注册，ARM64 用 ARM64X 混合二进制。
   https://learn.microsoft.com/zh-cn/windows/win32/tsf/64-bit-platform-considerations
2. **UWP/AppContainer**：注册 IMMERSIVESUPPORT category；DLL 必须在 Program Files 下；
   数据文件需给 ALL APPLICATION PACKAGES 读权限。
3. **DPI**：候选窗必须 per-monitor DPI aware 且跟随宿主进程的 DPI 感知模式。
4. **触摸键盘**：处理 PUA 键 0xF003/0xF004。
5. **light-dismiss** 三事件 + UIA 属性：
   https://learn.microsoft.com/en-us/windows/apps/develop/input/input-method-editor-requirements
6. **提权宿主**：管理员进程里的 TSF DLL 连接低完整性引擎进程，管道安全描述符要放宽。
7. **签名**：IME DLL 注入所有进程，是杀软重点盯防对象；发布前必须购买 Authenticode 证书。

## 协议策略

前端自研（自定协议）+ librime（BSD-3）+ SampleIME 骨架（MIT）+ 万象数据（CC-BY-4.0，署名）
= 除 octagram（GPL-3.0）外协议链干净。octagram 隔离在引擎服务进程内，
以独立 GPL 程序形式分发（进程边界 + IPC = 非衍生作品），前端保留全部选项。
